### Decisions taken (routine; the spec leaves these open)

- **Fixtures are TypeScript, not JSON.** §16 names `ballad-word.json` and so on. The docs are built
  from short annotated text (`har~bour*3` = two syllables, held 3×; `|` = a 600 ms rest) with a fixed
  pacing per fixture, because about 2,450 hand-typed timestamps would be error-prone and unreviewable.
  The names are kept as keys, the output is the same `LyricsDoc`, and the tests check every doc
  against the schema and the §5 repair rules.
- **Guide audio is generated, not committed.** All ten WAVs together are 43 MB. Task 3 can build the
  same samples in the browser (`guideTone()` is pure), and the script writes files on demand for the
  listening test.
- **`source: 'fixture'`** was added to the `LyricsDoc` source union (and to the spec) so mock docs
  never claim to be Navidrome or LRCLIB. Attribution reads "Fixture lyrics written for ECHO".
- **Which hand-over a coalesced line uses.** §9.9 says hand-overs < 350 ms apart advance the field
  two ranks at once, and that "each line still takes the active state for its time". `timing.ts`
  advances at the **later** hand-over: the short line sweeps at rank +1 (as close as allowed, like
  §9.9's overlapping lines) and then passes to −1. It never holds rank 0, and the line before it
  keeps the anchor a little longer. Advancing at the earlier hand-over would put the short line at −1,
  decaying, for its entire duration.
- **Gaps ≥ 7 s.** The line before the gap leaves the anchor at its `end` (§9.8 measures the gap from
  there), the dots take the anchor, and they leave 500 ms before the next hand-over. After the last
  line, the anchor is empty (§9.8: "the field then shows nothing").
- **Hand-overs never go backwards.** When two lines start < 180 ms apart, the §5.3 formula can put
  the second hand-over before the first; `timing.ts` keeps them non-decreasing. No fixture triggers
  this, and a test checks that the fixtures' hand-overs equal the raw formula.
- **Rank +1's approach** closes 35% of its clearance × drift and never moves *down*. If overflow
  shrinks the gap below 0.02 H, the clearance is treated as 0, so LYR-05's "y decreases
  monotonically" holds.
- **The interjections in `rap-word`** ("Yo", "Go", 102 ms) are the "two lines < 350 ms apart". They
  are outside §16's 0.9–1.8 s line range on purpose; every other rap line is inside it.

### Findings for the tuning session (task 11)

- **The gap factor barely varies on the main fixtures.** `gᵢ = clamp(Δstart / 3200, 0.8, 1.5)` only
  changes for lines 2.56–4.8 s apart. Every ballad line pair is ≥ 4.8 s apart (always 1.5), and every
  rap pair is ≤ 2.56 s apart (always 0.8). The LYR-04 check therefore runs on `duet-word`, where
  the factor varies. Whether "time becomes space" is visible enough on real ballads is a question
  for the tuning session.

### How the tests were checked

- The hand-computed table (`timing.test.ts`, first block) was worked out on paper from §5.3, §9.8
  and §9.9 before the code ran. It covers an intro with dots, a coalesced pair, an 8 s gap with dots,
  and the outro.
- For every timed fixture, 50 evenly spread times are compared with the spec formulas written out
  directly in the test (`expectedAt`), and ranks must be strictly increasing with exactly one rank 0
  when a line is active.
- Mutation check: breaking `timing.ts` in five ways was caught each time. The changes were the
  coalescing threshold (350 → 200 ms), the minimum lead (120 → 100 ms), the drift distance (×3), the
  +1 depth floor, and the minimum gap shrink. The first and third went undetected in the first
  version of the tests, so exact boundary and drift checks were added.
- Writing the fixture tests found a real gap: `accents-word` had `Ø` but no lowercase `ø`. The fixture
  was fixed, not the test.

### Decisions

- **Features tracks are functions, not JSON.** Recorded at 30 fps they would be about 1.7 MB of JSON
  for four tracks; as functions they are about 100 lines and give every frame exactly. The recording
  format of §10 still loads (`pulse.json`).
- **Onsets are sampled by interval.** A track reports an onset when a hit falls in `(t − dt, t]`, so
  each hit shows on exactly one frame at any frame rate, and a still frame (`dt = 0`) never shows one.
  The first version double-counted or missed hits that landed exactly on a frame boundary
  (floating-point `mod`); the unit test that counts onsets per bar caught it, and the fix is a 1 µs
  tolerance in the hit check.
- **Only guide tracks use real audio.** The existing albums keep the FakeProvider, so the M2 dock
  tests keep their exact virtual clock (`page.clock`); real media time cannot be faked that way.
- **Fixture capabilities stay `audioFeatures: false`.** The Features come from the fixture, not
  from an analyser; the analyser tap exists but is read from M5.
- **The lyric offset is not in `SongClock`.** §5.2 adds it "for lyrics only"; the lyric field adds
  it when offsets exist (LYR-25, M6), so the Stage keeps the un-offset clock.

### Decisions and readings (routine; the spec leaves these open)

- **Model and DOM are separate.** Everything that decides where a line is, how bright, and which word
  is lit lives in `model.ts` and is tested on 60 Hz frame simulations of whole fixtures. `field.ts`
  only writes the result.
- **Glow rules conflict, safety wins.** §5.2 asks for a 90 ms rise and "at most two words", while
  §12.5 caps glow changes at 1.5/s. The slew limit wins: a rise takes ≥ 233 ms, and when two words
  are still fading the older fades at the limit while the next word's glow waits. Cutting the third
  glow to zero (the first version) broke the limit and was caught by the test. Written into §5.2.
- **Glow is a `drop-shadow`, not a `text-shadow`** (the M1 specimen finding), coloured by a new
  derived token `--art-glow-solid`, so the field writes only an alpha. Written into §5.2.
- **Decaying lines.** A line that never held the anchor (coalesced) decays from +1's opacity, not
  from 1. Rank −2 stacks above −1 with the same 0.035 H gap (`decay.gapH`, added to §15).
- **Background motion.** The wandering paths and camera sway run on the Stage's pool clock, which
  slows to 25% while paused (§9.6, the loop's existing ramp). The slow rise and re-homing follow song
  time, so a seek lands on the same arrangement every time. A line entering +3 blends its opacity
  over the 760 ms `line.enter` move, so its corridor-capped opacity never jumps.
- **Background lines stay on stage**, and the corridor caps ease in just outside the corridor.
  Written into §8.2.
- **Duet sides** without flags: the first agent left, the others right; `group` agents centred.
  Written into §4.4.
- **The untimed sheet is React** (static text, focusable, part of the accessibility tree); the
  engine draws only timed documents.
- **The loop** keeps ticking for the lyric field in Still mode (reduced motion keeps the sweep) and on
  the CSS room. When the room cannot draw (no WebGL 2, a failed start, a lost context), the loop
  drops to Still, so with no lyrics showing it schedules nothing, as VIS-07's test requires.
- **Scrub** comes from the dock: the scrubber reports its live time to `scrubStore`, and the end of
  a drag counts as a seek (slow spring, no stagger).
- **Spring settle times** in §6.1 were wrong for `slow` and `enter` (0.75 and 0.85 s); the exact
  solution, checked against RK4, settles in 0.46 and 0.76 s. Table corrected; parameters unchanged.
- **The no-lyrics placeholder keeps M2's position** (40% of the stage, not of `H`). Moving it would
  re-baseline nine screenshots for text that Cover mode replaces in M6 (§9.4).
- **The wash eases with a quartic** standing in for `--ease-out`'s cubic-bezier (marked in code).

- **↓ turned the volume down instead of scrolling the focused lyric sheet** (§9.3). A focused

## Task 12: design review (2026-10-24)

45 deterministic frames: nine timed fixtures × five moments (intro, 10%, 45%, 80%, last line) at
1440×900, from `tests/e2e/review-shots.spec.ts` (`SHOTS=1 pnpm exec playwright test review-shots
--project=chromium`, PNGs in `test-results/review-shots/`). Not committed (≈ 15 MB).

### Findings

1. **The transition zone overlapped itself on wrapped lines.** Approach drift moved +2 and +3 30%
   toward the slot above with no clearance rule, so two-row lines slid into each other (ballad
   intro: "a small gold window" printed through the bottom of +1; rap: +2 through +3).
2. **+3 "waiting behind +2" (§4.3 overflow) read as a second line printed through +2**, at
   opacity 0.24 — noise, not depth.
