## SEC-10: the critical zlib finding

### What it was

| Field | Value |
|---|---|
| Trivy ID | **CVE-2023-45853** (CRITICAL from NVD, CVSS 9.8; Red Hat 5.3; Debian assigns no severity) |
| Package | `zlib1g` `1:1.2.13.dfsg-1` (source `zlib`), Debian 12 bookworm base `node:24.22.0-bookworm-slim` |
| Trivy status | `will_not_fix`, no fixed version |
| Affected component | **MiniZip** (`contrib/minizip`, `zipOpenNewFileInZip4_64`): integer overflow → heap overflow via a long file name, comment or extra field when **writing** a zip archive. MiniZip is not part of the supported zlib library |

### Was it present, reachable, applicable? (evidence from the image)

- **Not built:** Debian's tracker marks bookworm's zlib `<ignored>` because "contrib/minizip not built
  and src:zlib not producing binary packages". Independently checked: `libz.so.1.2.13` in the image
  contains **zero** `zipOpenNewFileInZip*` symbols, and no `libminizip` package or file exists.
- **Not loaded:** node, libvips, sharp and better-sqlite3 do not link the system `libz`. Node uses
  its own bundled zlib (1.3.2.1). With every native module loaded, `libz.so` is not in the
  process's memory map. Only Debian tooling depends on `zlib1g` (dpkg, apt, gpgv, util-linux).
- **Conclusion:** the vulnerable function was not present in any binary in the image, so the CVE
  did not apply. The finding came from mapping the CVE to the source package version.

### Remediation applied

Bookworm has no newer zlib. Two facts made a base update the defensible fix:

1. Debian 12 bookworm **left regular security support on 2026-07-11** and is now on LTS
   (debian.org/releases, wiki.debian.org/LTS). Debian 13 trixie is the current stable release, with
   security support until 2028-08-09.
2. Node publishes official `24.22.0-trixie(-slim)` images.

The base moved to `node:24.22.0-trixie(-slim)`, pinned by digest. Before adopting it, the candidate
passed the full hardware verification on the OptiPlex (native modules, Argon2id 184–188 ms, healthy
container). The final image was rebuilt and rescanned:

| Image | OS | CRITICAL | HIGH | of which fixable |
|---|---|---|---|---|
| before (bookworm-slim) | Debian 12.15 | 1 (zlib, MiniZip) | 56 | 0 |
| **final (trixie-slim)** | Debian 13.7 | **0** | **43** | **0** |

Not done, by instruction: switching to distroless, or changing the policy.

## Residual risk: 43 unfixed HIGH findings (accepted exception)

The owner accepted the proposed exception on 2026-10-23. The full record (every CVE, package and
installed version, scanner evidence, the reachability verification and its stated limits,
mitigations, owner, triggers, expiry at M9) is [`M1-SEC-10-exception.md`](M1-SEC-10-exception.md).
In short: HIGH CVEs with no Debian fix in util-linux, ncurses, systemd client libraries, libacl and
perl-base. Re-verified on the OptiPlex: ECHO's runtime loads none of the affected libraries and runs
none of the affected tools, and the setuid binaries cannot gain privileges under the hardening.
After code execution in the container they are still on disk, so the risk is reduced, not removed.

The critical finding needed no exception: it is no longer in the image, and the evidence shows it
never applied. Rejected alternatives for now: switching to distroless or stripping packages only to
improve scanner output. Any future base change needs its own justification and OptiPlex
verification.
