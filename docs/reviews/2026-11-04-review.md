## Still open

Security
- **S2.** yt-dlp updates itself daily (`ytdlp.ts` `updateYtdlp`) inside the container that can read
  the master key and the database, so a new upstream release runs in production within 24 h, past
  the project's two-week rule for dependencies. Cheapest first: keep the previous binary and roll
  back when a known public video stops resolving after `-U`; accept only releases a few days old
  unless the current one fails; a sidecar container with neither the key nor `/data`. Related: urgent
  resolves (the song being played) have no queue cap per user.
- **S3.** An admin deletes another user with the session alone (`admin.ts`); deleting yourself needs
  password + TOTP. §10 says "As delete my account": the owner to say whether that includes the step.
- Lockout: five wrong passwords lock an account (15 min, doubling to 24 h), so anyone who knows the
  admin's username can keep it locked from one address. A known trade-off; the owner to decide.

Correctness and performance
- **P1.** The matching sweep writes ~23k rows a day one transaction each (`spotifyMatch.ts`): one
  transaction per 500-song page; `synchronous = NORMAL` is safe with WAL.
- **P2.** The Navidrome proxy checks the URL (DNS, decrypt, allow-list) on every request: memoise
  per URL for a minute.
- **B6.** `staleSeen` (`youtube/catalogue.ts`) is shared by overlapping calls: a signed-out answer
  can be misreported. **B7.** NetEase lyrics live one day in the cache (no TTL entry, and none in
  `LYRICS_INTEGRATION.md` §7). **B8.** Removing a Wanted item is one tap, no undo, no audit.
- Suspicions, not reproduced: the 15 s socket idle timeout on Navidrome streams can cut a long
  transcode the browser stops reading; Node as PID 1 does not reap yt-dlp's grandchildren
  (`init: true`); `/data/tmp` is never cleaned of yt-dlp's unpacked folders after a hard stop.

Maintainability, tests, ops
- **M1.** Security checks in two copies: TOTP/recovery verification (`auth/routes.ts`,
  `account.ts`), the password check (login and device login), the Navidrome client loading.
- **M2.** The Android lyric engine (Model, Layout, Springs, Timing, Beat, Config) is hand-ported
  with no drift check (the shaders have one); Android has no CI job.
- **M3.** Stale comments: `admin.ts` header (Spotify settings), `config.ts` header, `main.tsx`
  ("no UI yet"), an orphaned JSDoc in `navidrome/routes.ts`, a duplicated one in `spotifyMatch.ts`,

- **O3.** CI never runs (no remote): gitleaks over history and the Trivy scan only by hand; a
